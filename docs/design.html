Deputy

A small Mac app that logs in to WhatsApp as you and lets Claude agents answer the chats and groups you give them. Each agent has its own git repo, and what it learns stays there.

Design for approval · built on Notted (Go + Wails + React) · repo github.com/GabiHert/positron (private) · 4 Nov 2026

01 · WHAT IT DOES

Three things, nothing more

  1. Connect WhatsApp. Scan a QR code once. Deputy becomes a linked device on your own number, the same as WhatsApp Web.
  2. Create agents. An agent is a name, instructions, a git repo for its knowledge, the chats it watches, and rules for when it answers.
  3. Let them work. When a watched chat gets a message, the agent's Claude Code run reads the recent conversation and its repo. It answers or stays quiet, and it can write what it learned back to the repo. You can see every message, reply and knowledge commit in Activity.

It uses your own Claude Code login, the same way Notted does. You don't need an API key.

02 · SCREENS

How it looks

The window has a sidebar with three views. It uses Notted's palette and type and follows the Mac's light or dark mode.

03 · ONE MESSAGE, START TO END

What happens when a message arrives

whatsmeowMessage inDeputy gets it from WhatsApp and adds it to that chat's history.
routerFind the agentThe agent that owns the chat. Its trigger rule decides if this message counts.
debounce 8 sWait for the burstPeople send three short messages in a row, so the agent answers once for all of them.
claude -pAgent runRuns in the agent's repo with the last 40 messages. Returns a reply or NO_REPLY.
gitReply + commitSends or queues the reply. Commits any repo changes, and pushes if a remote is set.

One run per chat at a time. Messages that arrive during a run go into the next run. Messages you send yourself are kept as context but never start a run, and the agent never answers its own messages. That keeps it from looping.

04 · THE AGENT RUN

How Claude Code is called

Deputy finds and launches claude the way Notted does: it reads the login shell's environment, drops ANTHROPIC_API_KEY so your subscription is used, and kills the process group on timeout.

cd ~/Documents/Personal/checagem-kb
claude -p --output-format json \
  --append-system-prompt-file <deputy protocol + agent instructions> \
  --permission-mode acceptEdits \
  --allowedTools "Read Write Edit Glob Grep WebSearch WebFetch" \
  < prompt.md      # chat name, last 40 messages, the new ones marked

The protocol tells the agent three things. Its final answer is the WhatsApp message, or exactly NO_REPLY. The repo is its memory: read CLAUDE.md and knowledge/ first and write lasting facts back. It doesn't run git, because Deputy commits for it.

The agent has no Bash and can't reach outside its repo, so a message in a group can't make it run commands on your Mac. You can turn on more tools for each agent.

05 · THE KNOWLEDGE REPO

Where knowledge grows

Pick an empty folder or an existing repo. If it's empty, Deputy sets it up:

checagem-kb/
├── CLAUDE.md          # who the agent is, how to keep knowledge (you and the agent both edit it)
├── knowledge/         # facts, people, decisions, FAQs, one topic per file
│   └── people.md      # who is who in the chats
└── .deputy/           # chat history snapshots the agent can grep (gitignored)

Each run that changes files becomes a commit such as Checagem: learned from "Fraude nas urnas" (2 files). Git history shows what the agent learned and when, and git revert undoes a bad lesson. Push to GitHub is optional for each agent.

Chat logs stay in Deputy's app folder and the gitignored .deputy/, never in a commit, unless you tell the agent to keep a summary.
06 · ARCHITECTURE

Built on Notted

Deputy starts as a copy of Notted and keeps its layers, its Wails setup, the Claude Code launcher, the git client and the build and signing scripts. The meeting parts (audio capture, transcription, forms, MCP) come out.

App data lives in ~/Library/Application Support/Deputy/. One app instance at a time, because two clients on one WhatsApp session break the link (the old bot learned this with bot.pid).

07 · ONE CHANGE FROM THE OLD BOT

whatsmeow instead of whatsapp-web.js

The old bot drives WhatsApp Web in headless Chrome through Puppeteer. It works, but most of bot.js handles that setup breaking: a pinned web version, a patch for the missing ready event, restarts on "detached Frame", and the _serialized to $1 rename.

whatsmeow is a Go library that speaks WhatsApp's multi-device protocol directly. Login works the same way (QR code, linked device, your number), but it runs inside the Go binary with no Node, Chrome or page to lose. It also powers the mautrix WhatsApp bridge, which is widely used.

Risk, same as the old bot: automating a personal account is against WhatsApp's terms, and an account that sends a lot of automated messages can be banned. Deputy limits each agent to 20 replies an hour by default, and new agents start on "After I approve".
08 · BUILD ORDER

Milestones

  1. Skeleton. Copy Notted, rename to Deputy, remove the meeting code, open an empty three-view window.
  2. WhatsApp. QR login, connection state, log out, list of chats and groups, incoming messages stored.
  3. Agents. Create and edit agents, set up the repo, assign chats.
  4. Runs. Router, debounce, Claude Code run, reply or NO_REPLY, commit after the run.
  5. Activity and approval. Feed, drafts with Send, Edit and Discard, notifications, rate limit.
  6. Polish. "Open repo in Claude Code", build and install with make install, README.

In v1

  • Photos go to the agent, which reads them with Claude Code.
  • Voice notes are transcribed on the Mac with Notted's local Whisper engine.
  • Agents can attach images from their repo and, optionally, answer with a spoken voice note.

Left out of v1

  • Documents and video. The agent sees the caption only.
  • Scheduled messages, or agents that start conversations.
  • More than one WhatsApp account.
